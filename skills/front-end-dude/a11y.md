# Accessibility — WCAG 2.2 AA deep reference

The real checklist, distilled from WebAIM / Deque / W3C. Level AA is the legal/contract baseline globally.

## Semantics

- Headings form a correct outline: one `h1`, no skipped levels (no `h1` → `h3`).
- Landmarks present and unique-labelled when repeated: `header`, `nav`, `main`, `footer`, `aside`, `search`, `form`.
- Native elements first — `<button>`, `<a href>`, `<input>`, `<details>`, `<dialog>`, `<select>`. Custom widgets are harder to get right and almost never worth it.
- If you must ARIA, follow the [ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/) pattern verbatim. Never invent roles.

## Keyboard

- Every interactive element reachable with Tab in a logical order (top → bottom, left → right in the reading direction).
- Visible focus indicator: ≥ 3:1 contrast against adjacent color, ≥ 2px offset ring (WCAG 2.4.11 "Focus Appearance").
- No keyboard trap: Tab out of any modal/drawer is always possible (Escape works).
- Arrow keys navigate composite widgets: tabs, menus, radio groups, listboxes, sliders. Implement the APG pattern.
- Escape closes any open transient UI (menu, popover, dialog). Focus returns to the trigger on close.

## Forms

- Every `<input>`, `<select>`, `<textarea>` has a programmatic label: `<label for="id">` or `aria-labelledby`.
- Do not rely on placeholder text as the only label — it disappears on focus and has insufficient contrast.
- Error messages: associated via `aria-describedby`, announced live (`aria-live="polite"` or `role="alert"` for urgent). Not conveyed by color alone.
- `autocomplete` attributes set for name/email/password fields (WCAG 1.3.5, also improves UX significantly).
- `required` attribute on required fields (not just a visual asterisk).

## Contrast

- Text: ≥ 4.5:1 for body text (< 18pt normal weight, < 14pt bold).
- Large text (≥ 18pt / ≥ 14pt bold): ≥ 3:1.
- UI components and graphical objects (borders, icons, input focus rings): ≥ 3:1 (WCAG 1.4.11).
- Check both light and dark modes if the project supports theme switching.

## Motion

- Respect `prefers-reduced-motion`. Wrap all non-essential animation in:
  ```css
  @media (prefers-reduced-motion: no-preference) { ... }
  ```
- No autoplay video with audio. No parallax. No auto-advancing carousels without pause control.

## Target size (new in WCAG 2.2)

- Interactive targets ≥ 24×24 CSS px (AA, SC 2.5.8). Aim for 44×44 on mobile (iOS HIG recommendation).
- Targets smaller than 24px must have 24px of non-overlapping offset space.

## Focus not obscured (new in WCAG 2.2)

- Sticky headers and fixed footers must not hide the currently-focused element (SC 2.4.11).
- Use `scroll-margin-top` on focusable elements when a sticky header is present.

## Skip links

- "Skip to main content" link as the first element in `<body>`.
- Visually hidden by default; visible on focus.
- `href="#main"` targets `<main id="main">`.

## Live regions

- Toasts / status messages: `role="status"` (polite) or `role="alert"` (assertive, for errors).
- Never use `aria-live="assertive"` for non-critical updates — it interrupts screen reader flow.
- Dynamic content that changes without page reload: announce via a live region or move focus to the updated section.

## Images

- Informative images: `alt` describes the content and function, not the file name.
- Decorative images: `alt=""` (empty string, not omitted). The browser treats omitted `alt` as the filename.
- Complex images (charts, diagrams): `alt` summarizes, plus a long description nearby or via `aria-describedby`.
- Icon fonts / SVGs used as icons: if meaningful, `aria-label` on the wrapper or title in the SVG. If decorative, `aria-hidden="true"`.

## Testing

- Automated: axe-core via `@axe-core/playwright` on each Playwright test, or `jest-axe` in component tests. Zero critical/serious violations is the bar.
- Manual keyboard walkthrough: Tab through the page top-to-bottom. Every interaction reachable? Focus visible? Composite widgets navigable?
- Screen reader smoke test: VoiceOver (macOS/iOS) or NVDA (Windows). Headings make sense as a list. Forms are usable. Dynamic updates are announced.
- Contrast: browser DevTools → Accessibility → Color contrast, or browser extensions (axe, Wave, Colour Contrast Analyser).
